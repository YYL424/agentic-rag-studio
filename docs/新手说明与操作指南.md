# Agentic RAG Studio：零基础说明与操作指南

## 一句话认识它

这是一个“会查资料的企业文档问答助手”。你先上传资料，再提问；它会从资料中找证据、必要时重新检索，并给出带来源编号的回答。它还支持人工审核新抽取的知识、删除文档和局部更新。

这里的 **Agent** 指按步骤调用模型和检索工具的应用程序。当前项目不训练或微调大模型，因此不是 Agent 后训练项目。

## 你能用它做什么

假设你上传了一份《员工手册》。你问“年假怎么算？”，系统会：

1. 理解问题，并把它改写成适合搜索的关键词。
2. 在向量库里找语义相近的段落，在知识图谱里查人、部门、规则之间的关系。
3. 合并、排序证据；如果证据不足，最多按配置重检有限轮次。
4. 根据找到的证据回答，并把 `[1]`、`[2]` 对应的文件名显示出来。

不要把“检索支持度 80%”理解成“答案有 80% 概率正确”。它是检索证据的启发式分数；重要结论仍要打开原文核对。

| 词 | 通俗解释 | 项目里的作用 |
|---|---|---|
| 大模型 | 会读写文字的模型 | 理解问题、抽取知识、生成回答 |
| Chunk | 文档中的一小段 | 让检索更精确，并定位来源 |
| 向量库 Qdrant | 按“意思相近”找段落 | 回答事实和文本问题 |
| 知识图谱 Neo4j | 保存“谁和谁有什么关系” | 回答关系、多跳问题 |
| RRF | 合并两份搜索结果的方法 | 避免直接比较不同数据库的分数 |
| Self-RAG | 发现证据不足时再查一次 | 减少凭空作答 |
| HITL | 让人审核后再入库 | 避免把错误抽取结果直接写进知识库 |

## 运行前准备

你需要 Docker Desktop、一个能调用的 OpenAI-compatible Chat API，以及项目源码。推荐用 Git Bash 执行下面的命令；`Copy-Item` 是 PowerShell 命令，Git Bash 中要用 `cp`。以下路径按本机目录写好，如果项目位置不同，请替换第一行。

```bash
cd "/c/Users/yyl/Desktop/Agent github/agent-knowledge-hub"
git status --short
docker info
```

本机已有 `python/.env` 时，直接编辑即可；没有时才复制模板：

```bash
cp python/.env.example python/.env
```

在 `python/.env` 中至少填写真正可用的 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`。保留模板中的假 key 会导致问答/知识抽取失败。新手可以先保留 `EMBEDDING_BACKEND=local`、`ENABLE_RERANKER=false`、`ENABLE_HITL=false`。不要将 `.env` 提交到 GitHub。

## 五分钟上手

在项目根目录运行：

```bash
docker compose up -d --build
docker compose ps
curl -i http://localhost:8080/api/health/ready
```

`ready` 返回 HTTP 200 表示 API、Qdrant 和 Neo4j 已就绪。第一次构建镜像和下载本地 embedding 模型可能较慢。如果一直没有 200，运行：

```bash
docker compose logs --tail=100 api qdrant neo4j
```

如果启动时报 `ports are not available`、`bind` 或 `access permissions`，表示 Windows 没允许绑定本机 `8080`，即使没有查到正在监听的进程也可能发生。无需删除数据或改 `python/.env`；在 **Git Bash** 中换一个宿主机端口重新启动：

```bash
API_HOST_PORT=18080 docker compose up -d
docker compose ps
curl -i http://localhost:18080/api/health/ready
```

随后把本指南中网页、API、烟雾测试或评测命令里的 `localhost:8080` 换成 `localhost:18080`。其中烟雾测试可运行 `powershell.exe -ExecutionPolicy Bypass -File ./scripts/e2e-smoke.ps1 -BaseUrl http://localhost:18080`。`API_HOST_PORT` 只影响电脑对外开放的端口，容器之间仍使用 `8080`。如果 `18080` 也无法绑定，先查 Windows 的端口占用与保留范围，再换一个未占用、未保留的端口；不要随意结束不认识的进程。

如果希望以后直接运行 `docker compose up -d` 仍使用 `18080`，可在**项目根目录**新建被 Git 忽略的 `.env`，内容为 `API_HOST_PORT=18080`。它与保存模型配置的 `python/.env` 是两个不同文件。

打开 [http://localhost:8080/](http://localhost:8080/)。先点击上传区域，选择一个 `.md`、`.txt`、`.pdf`、`.docx` 等文件；也可以拖入文件。等待页面显示“已入库”。然后输入一个答案确实存在于文档中的问题并点击发送。答案尾部会显示 `[1] 原始文件名` 这样的来源列表，正文中的 `[1]` 与列表第一条对应。

没有自己的测试文档时，可上传 `python/benchmarks/sample_docs/01-公司简介.md`，再问“星云科技什么时候成立？”。`sample_docs` 是虚构示例材料，里面提到的客户节约时间或成本只是演示文本，不能当作本项目的真实业务成效。

网页刷新后可在文档列表中查看已上传文件；不需要的文件可点删除。删除会清理受管文件及其向量、图谱来源。重复上传完全相同内容时，系统返回“已存在”，不会再次入库。

如果将 `ENABLE_HITL=true`，上传后会进入“等待人工审核”；在页面审核通过后才入库。默认的内存 checkpointer 仅适合本地演示，服务重启后挂起的审核流程不能保证恢复。

## 不用网页也能验证

在项目根目录运行自带烟雾测试，它会自动创建一份临时文档，验证上传、去重、问答和删除，并在结束时清理：

```bash
powershell.exe -ExecutionPolicy Bypass -File ./scripts/e2e-smoke.ps1
```

期望输出包含 `E2E smoke passed`。若 `python/.env` 设置了 `API_KEY`，先在当前 Git Bash 会话设置 `export AGENTHUB_API_KEY='你的值'`。不要把真正的 key 写在公开日志或截图里。

查看 API 接口说明：[http://localhost:8080/docs](http://localhost:8080/docs)。例如 `GET /api/documents` 看文档状态，`POST /api/qa/ask` 提问，`POST /api/admin/update` 手动触发受管文件更新。

## 如何拿到“优化了多少”的证据

仓库内的 [优化分析与实测](./优化分析与实测.md) 和 [原始 JSON](./evidence/qa_preprocessing_latency.json) 记录了并行预处理的本地模拟耗时。复测命令如下；运行前需在 `python/` 目录安装 `requirements-dev.txt`：

```bash
cd python
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe benchmarks/qa_preprocessing_latency.py \
  --dataset benchmarks/golden_set.jsonl \
  --samples 30 --runs 3 \
  --out ../docs/evidence/qa_preprocessing_latency.json
```

如果已经在 `python/.venv` 安装过依赖，省略创建环境和安装两行；本机若使用项目根目录的 `.venv`，把最后一行开头换成 `../.venv/Scripts/python.exe`。该脚本没有付费模型调用。每台电脑的运行时间会有差异。

如果要评测真实检索效果，先通过网页上传 `python/benchmarks/sample_docs/` 下的 **5 份**示例文档，然后在项目根目录运行：

```bash
docker compose exec api python benchmarks/agentic_ablation.py \
  --dataset benchmarks/golden_set.jsonl \
  --top-k 1,3,5 \
  --api-url http://localhost:8080
docker cp agenthub-api:/app/benchmarks/results/agentic_ablation.json python/benchmarks/results/agentic_ablation.json
```

`--api-url` 会把上传后生成的随机文件 ID 映射回原文件名，让“命中正确文档”的统计成立；缺少文档或出现同名多份时，脚本会报错。这个实验会调用配置的模型，可能产生费用。输出是召回证据的 Recall/MRR/NDCG 和耗时，仍不等于答案正确率。示例集只有 30 题，不可作为真实业务准确率写进简历。

## 常见问题

| 现象 | 先做什么 |
|---|---|
| `docker: command not found` | 启动 Docker Desktop；在新终端运行 `docker info`。 |
| Qdrant `unhealthy` | 运行 `docker compose logs --tail=100 qdrant`，看实际启动日志；不要直接删除数据卷。 |
| API 报 `ports are not available` | 按上方“换宿主机端口”的命令试 `18080`，并改用新地址访问。 |
| `/api/health/ready` 返回 503 | 运行 `docker compose ps` 和 `docker compose logs --tail=100 api qdrant neo4j`。 |
| 上传按钮没有反应 | 刷新 `http://localhost:8080/`，确认 API 已就绪，并打开浏览器开发者工具查看请求错误。 |
| 上传后问答报认证错误 | 检查 `python/.env` 的模型 key、base URL、模型名；再看 `docker compose logs --tail=100 api`。 |
| 问答没有找到资料 | 确认文件状态为“已入库”，问题确实可由文档回答；不要用检索支持度代替原文核查。 |
| 评测提示“缺失/同名多份” | 对照 `http://localhost:8080/api/documents` 检查 5 份示例文件是否全部成功入库且名称唯一。 |

停止服务用 `docker compose down`。这个命令默认保留数据卷；需要清空数据时先备份，别为了排错直接执行 `down -v`。

## 如果面试问项目成果

可以说：“我把两次独立的问答预处理模型调用并行化。在固定模拟等待时间、30 个问题重复 3 轮的本地测试中，工作流 P50 从 185.7 ms 降至 124.0 ms，降低 33.24%；90 次输出对比一致。下一步需在真实模型和数据库上验证实际收益。”

还可以说明：上传幂等避免相同内容重复入库，局部修改只重处理变化 chunk；这些流程效果在代码和测试中可查。没有实测数据时，不要声称节约了具体人工时间、模型费用或真实业务成本。
