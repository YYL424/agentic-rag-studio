# 星云科技研发流程规范

本规范适用于公司所有产品线的研发活动，覆盖需求评审、开发、测试、发布和线上事故处理全流程，自2024年1月起正式执行。

## 敏捷开发流程

公司采用两周一个迭代的敏捷开发模式。每个迭代从周一的需求评审会开始，产品经理在会上讲解需求文档和验收标准，研发团队在周三前完成技术方案评审。迭代内的开发任务拆解到半天粒度，每日早上10点进行15分钟站会，同步进度和阻塞项。迭代最后一天下午进行演示会，向产品经理和运营同事演示本迭代交付的功能。

需求变更遵循严格流程：小的变更由产品经理和技术负责人共同确认即可执行；涉及架构调整的变更必须提交技术委员会评审，评审周期不超过三个工作日。每个迭代允许的需求变更不超过总工作量的10%。

## 代码评审规范

所有代码合并必须经过至少一名同组同事的评审，涉及公共模块或接口变更的代码需要两名评审人。评审重点包括：接口设计的向后兼容性、异常处理的完整性、单元测试的覆盖情况。单次评审的代码量不超过400行，超过则需要拆分提交。

代码合并采用rebase策略保持主干线性历史。主干分支只接受通过全部自动化测试的代码，测试覆盖率的硬性要求是新增代码的行覆盖率不低于80%。评审意见必须在两个工作日内完成闭环，超时未处理会在周会上通报。

## 持续集成与发布

CI流水线在代码提交后5分钟内自动触发，包含代码检查、单元测试、集成测试和安全扫描四个阶段。全量流水线耗时约25分钟，其中单元测试约8分钟。流水线失败会阻断合并请求，并自动通知提交人和评审人。

发布流程采用金丝雀策略：新版本先发布到1%的流量验证两小时，指标正常后扩大到10%，再观察四小时后全量发布。发布窗口为每周二和周四的下午2点到6点，紧急修复走单独的快速通道，但需要值班负责人审批。回滚操作一键完成，平均回滚耗时3分钟。

## 线上事故响应

事故按影响范围分为P0到P3四级。P0事故指核心功能完全不可用或数据丢失，要求5分钟内响应、30分钟内定位、2小时内恢复。P1事故指核心功能部分受损，要求15分钟内响应、2小时内定位、6小时内恢复。P2和P3事故在24小时内响应。

事故处理采用指挥官机制：第一个收到告警的工程师自动成为事故指挥官，负责协调排查和沟通，直到事故解除。事故解决后48小时内必须完成复盘报告，报告包含时间线、根因分析、改进措施和责任人。复盘产生的改进措施进入项目管理系统跟踪，每两周检查一次完成率。

## 质量度量体系

研发效能平台每天自动采集关键指标：需求交付周期、代码评审耗时、流水线通过率、线上缺陷密度和事故恢复时长。这些指标在每月第一个工作日生成部门月度报告，连续三个月排名靠后的团队需要制定改进计划。线上缺陷密度按每千行代码的缺陷数计算，目标值低于0.5。
