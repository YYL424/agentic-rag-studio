# 星云知识中台技术架构设计

本文档描述星云知识中台的技术架构，涵盖微服务拆分、存储选型、消息机制和可观测性体系，供新入职工程师阅读。

## 微服务拆分

系统按业务域拆分为七个微服务：文档解析服务负责文件格式转换和OCR，抽取服务负责实体识别和关系抽取，检索服务负责向量召回和重排，图谱服务负责Neo4j读写和Cypher执行，问答服务负责LangGraph编排和大模型调用，审核服务负责人机协同审核流程，网关服务负责API路由、鉴权和限流。

服务间通信采用gRPC为主、REST为辅的双协议策略。文档解析和抽取之间的数据流通过Kafka消息队列解耦，解析完成的事件发布到doc-parsed主题，抽取服务消费后启动实体识别任务。消息采用at-least-once语义，下游通过幂等键去重，幂等键由文档ID和版本号组成。

## 存储选型

数据层分为四类存储。向量存储使用Qdrant，支持服务端集群模式和嵌入式本地模式，生产环境采用服务端模式部署三节点集群，向量维度1024，使用余弦相似度。图存储使用Neo4j社区版，部署单主两备，实体和关系分开存储，热点实体启用页面缓存。

关系型数据使用PostgreSQL 16，存储用户、权限、审核记录和配置信息。对象存储使用MinIO，存放原始文档、解析中间产物和快照文件，启用版本控制和生命周期策略，30天前的快照自动归档到冷存储。所有存储组件均启用数据加密，密钥由KMS统一管理，每季度轮换一次。

## 缓存与限流

检索服务内置两级缓存：第一级是进程内LRU缓存，容量10000条，存放高频查询的向量索引结果，命中率约35%；第二级是Redis集群缓存，存放查询改写结果和相关性评分，过期时间30分钟。缓存穿透通过布隆过滤器防护，不存在的文档ID直接短路返回。

网关层限流采用令牌桶算法，普通租户每秒100次请求，VIP租户每秒500次。限流粒度精确到API路径级别，超限请求返回429状态码并附带Retry-After头。熔断采用Sentinel，当检索服务错误率超过20%时熔断30秒，熔断期间请求走降级通道返回缓存结果。

## 可观测性

全链路追踪使用OpenTelemetry协议，Java服务和Python服务统一上报到Jaeger。每个检索请求生成唯一的trace ID，贯穿网关、检索、图谱、问答四个服务，追踪数据保留7天。指标采集使用Prometheus，关键指标包括检索延迟P95、召回率、大模型调用成功率和排队长度。

日志采用结构化JSON格式，通过Filebeat采集到Elasticsearch，按天索引保留30天。错误日志触发实时告警，P0级别错误通过短信和电话双通道通知值班工程师。全链路追踪、指标和日志通过trace ID关联，实现三维一体排查。每个季度进行一次混沌工程演练，验证降级链路和告警通道的有效性。

## 安全设计

系统采用零信任安全模型，所有服务间调用必须携带短时令牌，令牌有效期5分钟。文档访问控制细粒度到块级别，通过ABAC策略引擎动态判定，策略支持部门、职级、文档密级三个维度。审计日志记录所有文档的读取、下载和导出操作，保存期限三年，满足金融行业合规要求。

多租户隔离采用逻辑隔离方案，每个租户的数据通过租户ID字段隔离，向量检索在collection级别划分租户。关键租户可申请独占部署模式，获得独立的服务实例和存储集群。数据跨境传输遵循最小化原则，海外租户的数据存储在海外节点，不回流总部。
